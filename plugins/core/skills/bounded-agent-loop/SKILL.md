# Bounded agent loop

A human owns the goal and the gates. The runner owns iteration, verification, state, limits, and stopping. The agent never declares completion; the checks do.

Starter files, in this repository: `templates/core/loop/` (`run.mjs`, `goal.schema.json`, `goal.example.json`, `config.json`, `POLICY.md`, `adapters/`). Copy the folder to `.loop/` in the project. Node built-in modules only.

## 1. Install

1. Copy `templates/core/loop/` to `.loop/`
2. Add `.loop/runtime/`, `.loop/active-goal.json`, and `.loop/config.local.json` to `.gitignore`
3. Link `.loop/POLICY.md` from AGENTS.md so every agent reads the same gates
4. Keep only adapters for CLIs the user actually has. Each adapter is a short script: `<adapter> <prompt-file> <response-file> <workspace-root>`, exit 0 when the agent run finished

## 2. Write the goal with the user

Copy `goal.example.json` to `.loop/active-goal.json` and fill it in together:

| Field | How to decide it |
| --- | --- |
| `objective` | One outcome, in one or two sentences. Split larger work into several goals |
| `acceptance` | Checkable statements. Every one is required |
| `verification` | Commands that prove the acceptance criteria (lint, tests, structure checks, `git diff --check`). Human-authored, never generated by the agent during the run |
| `allowedPaths` | Where the agent may write |
| `forbiddenActions` | Project-specific "never" rules (personal config files, deleting features) |
| `limits` | Attempts, minutes, and how many identical verification results count as "stuck" |
| `humanGates` | Operations that stop the loop with `needs_human`: full renders, deletions, commit, push, merge, publish, external writes, new dependencies |

If the user writes requests in their own words, provide short request templates (feature, new component, adjustment) that end with "turn this into a loop goal and proceed until the criteria pass".

Validate: `node .loop/run.mjs --validate .loop/active-goal.json`. Preview the checks: `node .loop/run.mjs --goal .loop/active-goal.json --verify-only`.

## 3. Run

```sh
node .loop/run.mjs --goal .loop/active-goal.json --agent claude
```

- Prefer a dedicated git worktree for unattended runs; existing changes are listed in the prompt and must be kept
- The adapter's own permissions still apply. For Claude Code, `--permission-mode acceptEdits` allows edits; keep shell commands restricted in `.claude/settings.json`
- `--reset` starts a goal over; a finished goal (`complete`, `needs_human`) refuses to rerun without it

## 4. How it stops

| Status | Exit | Meaning |
| --- | --- | --- |
| `complete` | 0 | Every verification command passed (also when already true at the start) |
| `verification_failed` | 1 | `--verify-only` found failing checks |
| `budget_exhausted` | 2 | Attempt or time limit reached |
| `blocked` | 3 | The same verification output repeated (no progress), or the adapter failed |
| `needs_human` | 4 | The agent hit a gate and answered `NEEDS_HUMAN` |

## 5. Read the evidence

`.loop/runtime/<goal-id>/` holds `state.json`, an append-only `attempts.jsonl`, the exact `prompt-N.md` and `agent-N.md` of each attempt, `verification-N.json`, and `final-report.md`. Report the status, the reason, and the failing checks to the user; for `needs_human`, quote what the agent asked for.

## 6. Test the runner itself

When changing `run.mjs`, test each terminal state with mock adapters in a temporary folder: one that creates the expected file (complete), one that does nothing (blocked, then budget exhausted with a higher no-progress limit), and one that prints `NEEDS_HUMAN` (needs human).
